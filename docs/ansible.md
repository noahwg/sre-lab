# Ansible configuration

Terraform builds the host; Ansible configures it. There is no SSH: Ansible connects over SSM Session Manager using the `community.aws.aws_ssm` connection plugin, with file transfer through the S3 bucket Terraform creates.

## Layout

```
ansible/
  ansible.cfg           inventory path, roles path, become on
  requirements.txt      Python deps (installed into ../.venv)
  requirements.yml      collections (amazon.aws, community.aws, community.general, ansible.posix)
  site.yml              top-level playbook
  inventory/hosts.yml   GENERATED by `make up` (git-ignored)
  roles/
    base/               telemetry volume, swap, system hygiene, Docker
    edge/               Caddy: TLS (Let's Encrypt) and reverse proxy
    app/                the shortener container, pulled from ECR
```

More roles will be added in order: `postgres`, `app`, `monitoring` (VictoriaMetrics, VictoriaLogs, VictoriaTraces, Grafana).

## Usage

Python deps (`ansible-core`, `boto3`, `botocore`) are listed in `ansible/requirements.txt` and installed into a repo-local `.venv`. The Makefile puts `.venv/bin` on `PATH` for you, so there is nothing to activate. You still need the AWS CLI and `session-manager-plugin` installed system-wide.

```sh
make deps                          # one-time: creates .venv, installs Python deps and collections
make ping                          # verify the SSM connection
make check                         # drift check (--check --diff); run AFTER the first configure
make configure                     # apply everything
make configure ANSIBLE_ARGS="--tags swap"   # apply part of a role
```

The inventory supplies `telemetry_volume_id`, `telemetry_mount_point`, `primary_fqdn` and `fqdns` per host (see [terraform.md](terraform.md#the-inventory-stack)).

## Role: base

| Tag | What it does |
|---|---|
| `telemetry_volume` | Finds the EBS volume by ID (`/dev/disk/by-id/nvme-Amazon_Elastic_Block_Store_<id>`), creates an XFS filesystem **only if the device has none**, and mounts it at `telemetry_mount_point` with `noatime,nofail` |
| `swap` | 2 GB swap file on the root disk, persisted in fstab, `vm.swappiness=10` (the host has 2 GB of RAM) |
| `system` | chrony time sync, `dnf-automatic` for security-only updates, journald capped at 200 MB |
| `docker` | Docker from the AL2023 repos, pinned Compose v2 plugin, daemon `json-file` log rotation (10 MB x 3) and `live-restore` |

Defaults live in `roles/base/defaults/main.yml` (swap size, Compose version, journald cap, and so on).

### Notes

- **Idempotent.** A second run should report `changed=0`. Treat anything else as a bug.
- **Telemetry volume is safe to re-run.** The filesystem task never reformats a device that already has a filesystem, and `nofail` keeps the host booting if the volume is ever missing.
- **Compose plugin is downloaded** from the Docker GitHub release at a pinned version. Adding a checksum is a good follow-up.
- Docker's log driver is `json-file` for now. It will change once VictoriaLogs is running.

## Role: edge

Runs Caddy in Docker from `/opt/edge` and gets a Let's Encrypt certificate for each site automatically (HTTP-01 over port 80, which the security group already allows). Certificates and the ACME account are stored in `/var/lib/caddy` on the root disk.

| Variable | Default | Purpose |
|---|---|---|
| `edge_sites` | `[{host: primary_fqdn, upstream: ""}]` | Sites to serve. Empty `upstream` returns a placeholder; set e.g. `shortener:8080` to reverse-proxy |
| `edge_acme_staging` | `true` | Use the Let's Encrypt **staging** CA (untrusted by browsers, generous rate limits) |
| `edge_acme_email` | `""` | Optional expiry-notice address |
| `edge_caddy_image` | `caddy:2.10-alpine` | Pinned image |
| `edge_network` | `edge` | Shared Docker network; the app and monitoring projects join it as an external network |

Notes:

- **Prerequisite:** the DNS records from `make up` must already resolve to the host's Elastic IP, or issuance fails.
- **Going to a real certificate:** once the staging run works, `make configure ANSIBLE_ARGS="--tags edge -e edge_acme_staging=false"`. To make it permanent, set the variable in `ansible/group_vars/all.yml`.
- `/metrics` is answered with a 404 at the edge. Metrics are scraped on the internal Docker network.
- A Caddyfile-only change is applied with an in-place `caddy reload`, not a restart.
- **Switching between staging and production:** Caddy keeps serving any valid certificate it already has, whichever CA issued it. The role therefore deletes certificates from the CA you are *not* using and restarts Caddy so it obtains a new one. Flipping back to staging removes the production certificate too, so do that only for testing.
- The last task probes each site over HTTPS from the host (retrying while the certificate is issued) and fails the run if nothing answers.

### Verify

```sh
make configure ANSIBLE_ARGS="--tags edge"
curl -sk https://<primary_fqdn>/                 # "sre-lab edge ok" (-k while on staging)
curl -s -o /dev/null -w '%{http_code}\n' http://<primary_fqdn>/   # 308 redirect to https
openssl s_client -connect <primary_fqdn>:443 -servername <primary_fqdn> </dev/null 2>/dev/null | openssl x509 -noout -issuer
```

The staging issuer name contains "(STAGING)".

## Role: app

Deploys the shortener image from ECR behind Caddy. The deployed version is the single variable `app_image_tag` in `ansible/group_vars/all.yml` (format `shortener-<full commit sha>`), so what's running is recorded in git. Deploying a new build means changing that line; **rolling back means pointing it at an older tag**.

What it does, in order:

1. Refuses to continue unless `app_image_tag` is well-formed.
2. On **your machine**, using your AWS credentials: looks up the account ID (to build the ECR address) and reads the API key from SSM Parameter Store (`/sre-lab/shortener/api_key`). It refuses to deploy if the value is the `REPLACE_ME` placeholder or shorter than 16 characters. The instance role has no access to the parameter.
3. On the host: logs Docker in to ECR using the instance role, writes `/opt/shortener/app.env` (root only, mode 0600; the key never appears in Ansible output), and renders a compose file.
4. Starts the container on the shared `edge` network with no published ports, a 64 MB limit, a read-only filesystem, all capabilities dropped, and a healthcheck.
5. Waits for the container to report `healthy`, then checks `/healthz` and `/readyz` end to end through Caddy.

```sh
make deploy                                   # deploy the tag in group_vars/all.yml
make deploy APP_TAG=shortener-<sha>           # one-off override, e.g. a rollback
```

`group_vars/all.yml` also sets `edge_sites` to proxy to `shortener:8080`. That change is applied by the `edge` role, so the **first** deploy needs `make configure ANSIBLE_ARGS="--tags edge,app"`. Later deploys only need `make deploy`.

Storage is in memory for now, so links disappear when the container restarts.

### Try it

```sh
KEY=$(aws ssm get-parameter --name /sre-lab/shortener/api_key --with-decryption --query Parameter.Value --output text)
FQDN=$(terraform -chdir=terraform/env/labs/dns output -raw primary_fqdn)

curl -sk -XPOST https://$FQDN/api/links -H "x-api-key: $KEY" -H 'content-type: application/json' \
  -d '{"url":"https://example.com"}'
curl -skI https://$FQDN/<code>                # 302 to https://example.com
```
